# Implementation Roadmap M0–M10

| M | Capability | Exit evidence |
|---|---|---|
| M0 | v2 design/contracts | validator, Skills, schemas, source notices |
| M1 | desktop shell/event simulator | UI replay, motion/a11y baseline |
| M2 | local Qwen/vLLM gateway | pinned revisions, streaming, cancellation |
| M3 | Repo Intelligence | index/retrieval metrics and safety |
| M4 | analysis/onboarding | cited reports and architecture UI |
| M5 | bounded coding | hidden tests, rollback, review |
| M6 | Skill runtime/evaluation | paired validation and ablation |
| M7 | GitHub integration | approvals, draft PR, CI |
| M8 | UX/motion beta | performance, reduced motion, installer |
| M9 | full evaluation/quantization | quality-cost report |
| M10 | v1.0 | release gate, SBOM, checksums, clean install |

Implementation order is deterministic evidence before LLM, read-only before mutation, machine verification before remote delivery.

Detailed scope and gates are in the master design and `implementation/WORK_PACKAGES.md`.
