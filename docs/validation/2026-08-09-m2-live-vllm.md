- Maximum reported 8K request concurrency capacity: 7.55x; product profile remains bounded to one sequence.
- First successful cold/compile-assisted start: approximately 114 seconds from process start to application ready.
- Cached restart after served-model-name correction: approximately 85 seconds.
- Server bind: loopback only.
- API key is generated with mode `0600`, is redacted from logs, and is inserted into in-memory CLI arguments by `scripts/launch_vllm.py`; a `/proc/*/cmdline` scan found zero matches.

## Failure taxonomy and resolution

1. Initial start was stopped after vLLM echoed the ephemeral API key in its argument log. The key was invalidated and deleted before restart.
2. Log redaction alone was insufficient because a CLI secret is visible in process metadata. The launcher was changed so the key never enters the operating-system command line.
3. FlashInfer 0.6.14 sampling JIT failed with both the system CUDA 12.0 compiler and the environment CUDA 13.3 compiler because neither matched the Torch CUDA 13.0 headers. vLLM's documented native sampler fallback was selected with `VLLM_USE_FLASHINFER_SAMPLER=0`. BF16, FlashAttention, Qwen GDN kernels, context length, model revision, and structured generation were not downgraded.

No secret value is preserved in this record or experiment artifacts.
