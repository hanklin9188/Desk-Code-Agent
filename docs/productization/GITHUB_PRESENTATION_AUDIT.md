# GitHub Repository Presentation Audit

Date: 2026-08-12  
Result: `PASS_LOCAL_PRESENTATION`

## First-visitor path

The repository root deliberately surfaces three human entry points: `README.md`, `BENCHMARKS.md`, and the README-linked `docs/README.md`. The README then routes readers to architecture, capability status, visualization, media/demo, and the active execution plan before historical evidence.

| Visitor question | Canonical entry point |
|---|---|
| What is this? | `README.md` hero and positioning |
| What can it actually do? | `docs/productization/CAPABILITY_STATUS.md` |
| What evidence supports that? | `BENCHMARKS.md` |
| How does it work? | `docs/architecture/PRODUCT_ARCHITECTURE.md` |
| Can I see the workflow? | `docs/media/README.md` and capture manifest |
| Where are detailed docs? | `docs/README.md` |
| Where is historical research? | Links from `BENCHMARKS.md`, then `docs/experiments/` |

## Root audit

- The first README screen contains the product name, exact one-line positioning, and lightweight cover media.
- The README explicitly rejects Codex-replacement and autonomous-developer positioning.
- Benchmark terminology separates valid action, syntax, behavioral verification, and strict success.
- Capability states use Production, Assisted, Research Only, and Disabled.
- Autonomous mutation and the preregistered reliability threshold are prominent.
- Historical experiments remain available but are not the recommended starting point.
- No binary screenshot/GIF placeholder is linked as if it already existed.
- Canonical GitHub target is stated, but no remote/push/publication claim is made.

## Deferred protected work

Repository topics, social preview, final PNG/GIF assets, GitHub About text, remote branch presentation, and publication checks require an approved external GitHub action. They are prepared by the local media and README contracts but were not executed.
