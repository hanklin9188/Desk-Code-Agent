## Problem and audience

Desk Code Agent has a substantial sealed evaluation record, but an outside reader cannot yet move cleanly from product claim to measured evidence. The desktop shell also presents a useful engineering workflow without a coherent research dashboard. This phase turns the existing evidence into an inspectable product narrative for developers, evaluators, and portfolio reviewers. It does not change the model, harness, routing, or capability admission decisions.

## Domain boundary

The work is a read-only projection over sealed JSON artifacts. It may normalize and aggregate those artifacts into chart view-models, but it must not rewrite them or reinterpret a failed gate as product support. Live model inference, benchmark execution, new task generation, model acquisition, mutation enablement, packaging, and external publication are outside scope.

## Canonical decisions

- The final product architecture is local-first, evidence-first, and verification-first. One shared local model is wrapped by deterministic repository intelligence, bounded tools, typed events, approval, verification, and rollback.
- Structured cross-file planning is supported only inside its machine-checkable development boundary. Complete-context navigation is assisted. Diagnosis synthesis, onboarding synthesis, and mutation are report-only at the current admission boundary.
- No tournament model was promoted. FIM-7B is the strongest scored research candidate at 29/95, not a production model or mutation route.
- Privacy-safe L1 features improved supported semantic coverage from 0/44 to 15/44 while retaining zero raw model outputs and zero raw edit bodies.
- The final code-formation recovery stopped at its non-primary sanity gate. It consumed zero primary calls and supports no formation-effect conclusion.
- Autonomous mutation remains disabled. This must remain visible in the UI and documentation.
